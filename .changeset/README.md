# Changesets

Hello and welcome! This folder has been auto-generated by [@changesets/cli](https://github.com/changesets/changesets):

> _Three workspace packages ship in lock-step. Bumping `core` is also bumping `desktop` and `copilot`._

## Adding a changeset

When you make a change worth mentioning, run:

```bash
yarn changeset
```

It will ask which packages need bumping (semver) and ask for a one-sentence summary of the change. That writes a markdown file under `.changeset/` — commit it alongside your change.

CI runs `yarn changeset:status` on every push to surface any pending changes that lack a changeset entry. A PR with un-bumped changesets is a release blocker.

## Releasing

When you are ready to cut a release:

```bash
yarn changeset:version    # consumes all .changeset/*.md, bumps root + every package to the same version
yarn changeset:publish   # (only for npm-published packages — desktop/copilot are sideloaded)
yarn changeset:tag       # git tag every workspace's release
```

The `version-packages` script (`yarn changeset version`) is configured for **fixed** versioning: every package is bumped together, regardless of which packages the individual changesets touched. That keeps `@wbaw/core`, `workbuddy-anywhere-for-copilot`, and `@wbaw/desktop` shipping in lock-step.

## CI

`.github/workflows/ci.yml` runs:
- `yarn install` → `yarn build` → `yarn test:core` → `yarn lint`
- `yarn changeset:status` (fails the build when there are pending un-bumped changesets)
